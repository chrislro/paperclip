## What you (user) must do manually

### Step 1 — Live-shift smoke (30 min, before submit)

Confirm popup-driven Clerk sign-in actually works on your machine:

1. `chrome://extensions` → ↻ reload Toca Ficha Dr.
2. Click toolbar icon → popup
3. Click "Entrar / Cadastrar"
4. Clerk modal opens — sign up with your real email
5. Click verification link in email
6. Return to popup → should show your email + "Plano: FREE"
7. Open a G-Hosp patient chart → record a 15-second test consultation
8. Verify SOAP comes back, prescription template flow works, atestado flow works, finalize-patient discharge flow works

If any of these break, paste the popup DevTools console error and I'll diagnose.

### Step 2 — Capture 5 screenshots (1280x800)

Web Store requires 1-5 screenshots. Recommended set:

1. **Sign-in flow** — popup with "Entrar / Cadastrar" button visible (Clerk's branded sign-up modal mid-flow is also fine if it doesn't show your real email)
2. **HUD floating panel on G-Hosp** — anonymized patient chart (blur the patient name/ID in your image editor)
3. **Recording in progress** — HUD with timer running
4. **SOAP applied** — G-Hosp's SOAP fields populated, with the Toca Ficha HUD beside
5. **Prescription template editor in popup** — the modifiable template UI from `popup.html`

Resolution: 1280x800 PNG. Save to `store/screenshots/`.

**Anonymization rule**: blur or pixelate any real patient name, CPF, or chief complaint. Use placeholder data ("Paciente Teste, 5 anos, febre h.j") if necessary.

### Step 3 — Promotional tile (440x280) — optional but recommended

A single image with the brand color (`#0891B2` teal), logo, and one-line value prop ("Reduza 25-35 ações por paciente para 4-6"). Helps featured-tile placement. Skip if low-effort screenshots are blocked.

### Step 4 — Configure Clerk webhook (optional, can ship without)

For full lifecycle sync (`user.deleted` → DB cleanup, `user.updated` → email change sync), configure the webhook in Clerk:

1. https://dashboard.clerk.com/ → Configure → Webhooks
2. Add Endpoint
3. URL: `https://api.tocafichadr.com.br/clerk/webhook` (use the current tunnel URL only if `api.tocafichadr.com.br` is not yet resolving)
4. Subscribe to: `user.created`, `user.updated`, `user.deleted`
5. Copy the "Signing Secret" (`whsec_...`)
6. Run on Mac Mini (SSH OK):
   ```bash
   /usr/libexec/PlistBuddy -c 'Add :EnvironmentVariables:CLERK_WEBHOOK_SECRET string whsec_...' \
     ~/Library/LaunchAgents/com.pedbot.cloud-api.plist
   launchctl bootout gui/$(id -u)/com.pedbot.cloud-api
   launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/com.pedbot.cloud-api.plist
   ```

Without this, the Backend lazy-provisions on first auth (which works) but doesn't auto-sync subsequent email/name changes from Clerk.

### Step 5 — Submit to Chrome Web Store

1. https://chrome.google.com/webstore/devconsole
2. Sign in with the developer account
3. Click "Add new item" or open the existing Toca Ficha Dr. listing
4. Upload `tocafichadr-v3.4.0.zip` (in the repo root)
5. Fill out store listing using `store/description.txt` (copy/paste short + long descriptions)
6. Upload the 5 screenshots from Step 2
7. Upload promotional tile from Step 3 (if available)
8. **Privacy practices**:
   - Single purpose: "Automate pediatric EMR workflows in G-Hosp"
   - Permission justifications:
     - `activeTab`: needed to inject the HUD on G-Hosp tabs
     - `storage`: stores user prefs (auto-clear, auto-CID, prescription templates) and Clerk session
     - `scripting`: dynamic content script injection on G-Hosp navigation
     - `clipboardWrite`: copy SOAP output to clipboard for fallback paste workflow
   - Data usage:
     - Personally identifiable information: yes — email + name (for account, via Clerk)
     - Health information: NO — clinical data never leaves the doctor's browser/our backend
     - User activity: yes — usage counts (anonymized, for plan tier enforcement)
9. **Privacy policy URL**: `https://tocafichadr.com.br/privacidade`
10. Submit for review (1-3 business days)

### Step 6 — After Web Store approval

1. Get the **production extension ID** from the Web Store listing (it's stable, different from the dev ID `dldnbfjpobloegmdockjpbmpmgaahgan`)
2. Add it to Clerk's `allowed_origins`:
   ```bash
   SECRET=$(security find-generic-password -a clerk -s pedbot-clerk-secret-key -w)
   curl -X PATCH https://api.clerk.com/v1/instance \
     -H "Authorization: Bearer $SECRET" \
     -H "Content-Type: application/json" \
     -d '{"allowed_origins":["chrome-extension://<production-id>","chrome-extension://dldnbfjpobloegmdockjpbmpmgaahgan"]}'
   ```
   (Keep both dev and prod IDs during the rollout window; remove dev later.)
3. Update Mac Mini `CLERK_AUTHORIZED_PARTIES` plist value to include the production extension ID
4. After 24-48h of v3.0.x clients dominating traffic, flip `TOCAFICHADR_AUTH_REQUIRED=true`
