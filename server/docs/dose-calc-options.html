Dose calculator — UX options
5 layouts for weight-based pediatric + fixed-dose adult medications
v3.4.0 proposal · 2026-05-07
Backend already has /api/dosages/full?weight=X (12 pediatric meds: amoxicilina ×2, amoxi+clav, cefalexina, azitromicina, ibuprofeno, dipirona, paracetamol, prednisolona, dexametasona, ondansetrona, salbutamol). Returns weight-based dose, mL, gotas, "1 gota/kg" practical rules, frequency, duration, presentation. Adult dosing requires a parallel ADULT_MEDICATIONS list — most adult meds are fixed-dose (no weight multiplier), so the schema differs.
  • Patient age + weight already extracted from G-Hosp DOM and shown in the side panel.
  • No weight + adult age → show fixed-dose adult list. No weight + pediatric → prompt for weight.
  • Click any dose → copy to clipboard. Optional second action: "✚ Adicionar à receita" injects into #modo_usar on the next prescription.

My recommendation
LayoutStrengthWeaknessBest for
A Compact when collapsed; clean by category. Doctor needs to expand 4 sections. Very crowded side panel.
B Auto-defaults by age; one tab = one list. Fastest scan. 5+ rows always visible — uses vertical space. Generalist daily use. Auto-picks pediatric vs adult. Doctor sees the full active list at a glance.
C Power-user fast. Doctor must remember drug name; no browse. Doctors who already know what they want.
D Pins the most-used calculations to top. Two-tier hierarchy adds complexity. If 80% of dose lookups are dipirona/paracetamol/ibuprofeno.
E Maximum scan density; details on demand. Click overhead to see notes. Very large dose lists (20+ meds).

My pick is B (Tabbed) with the "Pediátrico" tab auto-selected when patient age < 18, "Adulto" when ≥18, "Tudo" reachable via one click. It's the smallest cognitive load for a generalist who sees both populations on the same shift. Each row's "✚" adds the prescription line to a draft buffer; the doctor opens "Receita" when they're done picking and the buffer is injected into #modo_usar.
