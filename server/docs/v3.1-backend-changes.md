## 1. New endpoint: `POST /api/soap-stream` (idea #3)

Streaming Server-Sent Events version of `/api/format-soap`. Same input model, same auth, same prompt assembly — just `stream=True` on the OpenAI call and SSE framing on the response.

### Request body (JSON)

```json
{
  "raw_text": "...",
  "chief_complaint": "...",
  "custom_instructions": "...",
  "soap_voice": {
    "id": "voice_silva_ps",
    "name": "Dr. Silva — PS",
    "verbosity": "medio",
    "perspective": "impessoal",
    "emphases": ["red-flags"],
    "customRules": "Sempre incluir escala de dor 0-10.",
    "fewShots": [
      { "complaint": "...", "output": "..." }
    ]
  }
}
```

`soap_voice` is optional. When absent, fall back to the existing default prompt.

### Response

`Content-Type: text/event-stream` with frames:

```
data: {"t": "S — "}\n\n
data: {"t": "Mãe relata"}\n\n
...
data: [DONE]\n\n
```

### Reference Flask handler

```python
from flask import Response, request, jsonify, stream_with_context
import json

@app.route("/api/soap-stream", methods=["POST"])
@require_auth  # existing decorator
def soap_stream():
    payload = request.get_json(force=True) or {}
    raw_text       = payload.get("raw_text", "")
    complaint      = payload.get("chief_complaint", "")
    legacy_instr   = payload.get("custom_instructions", "")
    voice          = payload.get("soap_voice")  # may be None

    msgs = build_soap_messages(
        raw_text=raw_text,
        chief_complaint=complaint,
        legacy_custom_instructions=legacy_instr,
        soap_voice=voice,
    )

    client = build_openai_client()

    def generate():
        try:
            stream = client.chat.completions.create(
                model="gpt-4o-mini",
                messages=msgs,
                temperature=0.1,
                max_tokens=600,
                stream=True,
            )
            for chunk in stream:
                if not chunk.choices:
                    continue
                delta = chunk.choices[0].delta.content or ""
                if delta:
                    yield f"data: {json.dumps({'t': delta})}\n\n"
            yield "data: [DONE]\n\n"
        except Exception as e:
            yield f"data: {json.dumps({'error': str(e)})}\n\n"

    return Response(
        stream_with_context(generate()),
        mimetype="text/event-stream",
        headers={
            "Cache-Control": "no-cache",
            "X-Accel-Buffering": "no",  # disable nginx/Cloudflare buffering
            "Connection": "keep-alive",
        },
    )
```

### Cloudflare tunnel note

Cloudflare buffers `text/event-stream` only when content-type is missing or wrong. The header above is correct, so streaming works through the tunnel. If you see tokens batched, double-check `mimetype="text/event-stream"` and the absence of `gzip` middleware on this route.

## 2. SOAP voice prompt assembly (idea #8)

Add a single helper that consumes the `soap_voice` field and produces the `messages[]` array. Centralizes verbosity / perspective / emphasis / customRules / few-shot logic.

### Reference

```python
VERBOSITY_RULES = {
    "curto":  "Cada seção deve ter 1-2 frases. Sem redundância.",
    "medio":  "Cada seção deve ter 2-4 frases. Cobertura clínica completa, sem prolixidade.",
    "longo":  "Cada seção deve ter 4-6 frases. Inclua contexto e justificativa.",
}

PERSPECTIVE_RULES = {
    "1a":         "Use primeira pessoa (eu observei, prescrevi).",
    "3a":         "Use terceira pessoa (paciente refere, foi observado).",
    "impessoal":  "Use voz impessoal/passiva (refere, foi observado).",
}

EMPHASIS_RULES = {
    "red-flags":      "Destaque sinais de alarme em A. Em P, mencione critérios de retorno imediato.",
    "sinais-vitais":  "Em O, sempre liste FC, FR, SatO2, T, PA quando disponíveis. Comente alterações.",
    "contexto-social":"Em S, inclua contexto familiar/escolar/laboral relevante.",
}

SOAP_TEMPLATE_BASE = """
Você é um médico assistente que organiza notas SOAP em PT-BR.
Estruture em 4 seções: S (subjetivo), O (objetivo), A (avaliação), P (plano).
PROIBIDO inventar sintomas, durações, localizações, quantidades não ditos.
Se algo não foi mencionado, omita — não invente.
"""

def build_soap_messages(raw_text, chief_complaint, legacy_custom_instructions, soap_voice):
    voice = soap_voice or {}
    verbosity   = voice.get("verbosity", "medio")
    perspective = voice.get("perspective", "impessoal")
    emphases    = voice.get("emphases") or []
    custom      = voice.get("customRules", "")
    few_shots   = (voice.get("fewShots") or [])[:3]

    parts = [SOAP_TEMPLATE_BASE.strip()]
    parts.append(VERBOSITY_RULES.get(verbosity, VERBOSITY_RULES["medio"]))
    parts.append(PERSPECTIVE_RULES.get(perspective, PERSPECTIVE_RULES["impessoal"]))
    for e in emphases:
        if e in EMPHASIS_RULES:
            parts.append(EMPHASIS_RULES[e])
    if custom:
        parts.append(f"Regras pessoais do médico: {custom}")
    if legacy_custom_instructions:
        parts.append(f"Instruções legadas: {legacy_custom_instructions}")

    msgs = [{"role": "system", "content": "\n\n".join(parts)}]

    # Few-shots — highest-leverage personalization. The doctor's own SOAPs
    # train the model on their writing style in-context.
    for ex in few_shots:
        if not ex.get("complaint") or not ex.get("output"):
            continue
        msgs.append({"role": "user",      "content": ex["complaint"]})
        msgs.append({"role": "assistant", "content": ex["output"]})

    # The actual transcript to format.
    user_msg = raw_text
    if chief_complaint:
        user_msg = f"Queixa principal: {chief_complaint}\n\nTranscrição:\n{raw_text}"
    msgs.append({"role": "user", "content": user_msg})

    return msgs
```

## 3. Backwards compatibility

- All new fields are **optional**. Old extension versions that don't send `soap_voice` continue to work — the helper falls back to the medio/impessoal default.
- The new `/api/soap-stream` endpoint is additive. The existing `/api/format-soap` (non-streaming) stays intact for the transcribe response shape.
- Bearer auth path is unchanged — `@require_auth` decorator on the new endpoint.

---

## 4. Test plan

- [ ] `/api/soap-stream` with no `soap_voice` → matches existing `/api/format-soap` output.
- [ ] `/api/soap-stream` with `verbosity=curto` → output ≤ 4 short sentences.
- [ ] `/api/soap-stream` with 2 few-shots → output mimics the example writing style (verify by eye).
- [ ] First token arrives in < 500ms (under typical Cloudflare tunnel conditions).
- [ ] `[DONE]` frame fires on completion.
- [ ] Error during stream → `data: {"error": "..."}\n\n` frame, then connection closes cleanly.

---

## 5. Why this lands

- **Streaming SOAP** is the single biggest perceived-latency win in the product. 1.5-3s blank → ~300ms to first token.
- **SOAP voices** is what doctors have wanted forever — finally getting the model to write in *their* style, not a generic one. Few-shots are the lever; the rest is decoration.
