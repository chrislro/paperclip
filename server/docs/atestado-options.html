Atestado — UX options
4 layouts for the days quick-pick + auto-Save+Print flow
v3.4.0 proposal · 2026-05-07
Logger evidence (n=173 atestado opens across 3 shifts):
  • Modelo always = 1 ("Atestado padrão") — 173/173. No mode toggle needed.
  • Days field: #nro_dias (free-text input) — defaults to 1, edited only in 31% of cases.
  • Days distribution: 1d 69%, 2d 19%, 3d 7%, 4-6d rare, never 7+.
  • Companion mode handled entirely by typing into #presatestado_obs (already auto-filled by v3.1.7).
  • Setting #nro_dias programmatically must dispatch change so the calc_data_fin XHR fires before Gravar.
Goal: one click → atestado printed. Pick the layout that best fits the 230-1000px side panel.
A
Drawer below Atestado action — quick-picks 1-6 + Outro override
~2 h Recommended
Click "Atestado ▾" reveals an inline panel with 6 day chips (covering 99% of usage) plus an "Outro" override for the 1% case. Selecting a chip drives the full automation: open dialog → Inserir → set #nro_dias → companion auto-fill (v3.1.7) → Gravar → IMPRIMIR.
Pros
  • Couples trigger to days input — visually obvious.
  • Default of 1 means "click Atestado, click 1, done" in 3 clicks.
  • Fits in narrow side panel (230px) without horizontal squeeze.
Cons
  • Adds vertical space when expanded (but only on Atestado clicks).
  • Drawer state needs to remember last choice for the same patient.

B
Number input + button — always visible
~1.5 h
Skip the drawer entirely. Replace the single Atestado action with a row showing a tiny "Dias: [1]" number input next to a "Gerar atestado" button. The doctor types or steps the number, clicks Gerar — same one-click automation runs.
Pros
  • No drawer state — always one click + one number entry.
  • Smallest vertical footprint of the four options.
Cons
  • Loses visual parity with the other 3 action buttons (Salvar, Receita, Baú).
  • Number input on tiny side panel needs precise click — easy to mistarget on touch.

C
Dedicated "Atestado" section above Ações
~2 h
Promote Atestado out of the action grid into its own section, since it has more configuration than the other actions. Same chips + button as Option A but always visible (no expand/collapse). The original Atestado button in the grid disappears.
Pros
  • No drawer state needed — always there, always ready.
  • Acompanhante context visible at a glance.
Cons
  • Adds permanent vertical space (~80px) even when atestado isn't being used.
  • Atestado is used 173× / 17 patients per shift = ~10/shift — not worth always-visible.

D
Modal overlay — bigger touch targets
~2.5 h Heaviest
Click "Atestado" → modal overlays the side panel with large day buttons (6 chips ≥40×40px). Solid choice for touch / small screens / one-handed use. Heavier UX than the drawer; obscures the rest of the panel.
Pros
  • Bigger touch targets — easier on a tablet.
  • Forces focused attention on the day choice (no other UI distracts).
Cons
  • Modals are heavyweight for a simple choice.
  • Doctor can't see the patient card while the modal is open.
  • Closing it requires an explicit action — friction for power users.
