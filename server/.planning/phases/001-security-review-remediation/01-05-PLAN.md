<objective>
Close two popup-level correctness issues:

1. **P1-11** — `chrome.storage.sync.set({ prescriptionTemplates })` has no completion callback. The `storage.sync` per-key quota is 8 KB; ~10 templates of 700 chars saturates it. When exceeded, the call fails silently (`chrome.runtime.lastError` set, data not persisted). The doctor keeps editing and nothing saves.

2. **P1-12** — Input event handlers in `renderRxTemplates` close over the render-time `idx`. Deleting a row triggers a full re-render; focus is destroyed; input events mid-typing land on the stale closure's index, which after the splice may point to an undefined element or the wrong template. Re-key handlers by `tpl.id` so they look up the live template rather than rely on position.

Purpose: make template editing robust against quota failures and concurrent edits+deletes.
Output: updated `popup/popup.js` with a save-error pathway and id-keyed handlers.
</objective>

Locate `renderRxTemplates` (around line 236). Its current handlers look roughly like:

```js
nameInput.addEventListener('input', () => {
  rxTemplates[idx].name = nameInput.value;
  saveRxTemplatesDebounced();
});
bodyArea.addEventListener('input', () => {
  rxTemplates[idx].body = bodyArea.value;
  saveRxTemplatesDebounced();
});
```

Refactor each handler so it looks up the template by id at event time:

```js
nameInput.addEventListener('input', () => {
  const target = rxTemplates.find(t => t.id === tpl.id);
  if (target) {
    target.name = nameInput.value;
    saveRxTemplatesDebounced();
  }
});
// same pattern for bodyArea
```

If existing templates in `chrome.storage.sync` don't have `id` (pre-rename artifact), synthesize one at load time: iterate the loaded array once and do `if (!t.id) t.id = _genId();` where `_genId` returns `'tpl-' + Math.random().toString(36).slice(2, 10)`. Save the synthesized id back so subsequent loads are stable.

Do NOT change the render loop structure, add/remove buttons, or the debounce interval.
