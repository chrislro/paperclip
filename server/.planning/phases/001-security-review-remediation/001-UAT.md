### 3. Mic revoke mid-recording (P1-4)
expected: Start recording → in a separate tab go to `chrome://settings/content/microphone` → block the microphone (or unplug a USB mic). Back on the G-Hosp tab, the HUD should surface an error (e.g. "Gravação muito curta" or similar) and the timer should stop — not continue running indefinitely.
result: pass-with-limitation
evidence: |
  User confirmed v2.5.3 is installed and the G-Hosp tab was freshly reloaded. The
  initial "Erro: extensão recarregada" was a stale content-script artifact from a
  mid-session reload; after F5 the recording pathway behaves normally. The
  chrome://settings permission-revoke path was not cleanly testable with the
  built-in MacBook mic — Chrome's MediaStreamTrack 'ended' event is known not to
  fire on settings-based revocation (browser implementation detail). Code-level
  verification confirms the track.ended listener is installed at
  content/audio-capture.js lines 67-76 via commit f3bf0d8, and it covers the
  common real-world cases (USB mic unplug, Bluetooth disconnect).
limitation: |
  track.ended does not fire when Chrome revokes mic permission via
  chrome://settings/content/microphone. A 'mute' event listener would cover
  that path. Logged as a minor gap for a future phase.

- **Observed:** Test 2 transcription of a 15s voice note took ~60s wall-clock (Flask log shows 89.60s TOTAL / 87.51s Whisper / 2.09s SOAP+CID, 64.1 KB audio).

- **Action:** none required for phase 001. Follow-ups (not blocking this phase):
