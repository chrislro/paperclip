<objective>
Close finding P1-4: `audio-capture.js` does not observe `MediaStreamTrack.ended`. If the microphone stream dies mid-recording (permission revoked via Chrome settings, tab suspended, device unplugged), the `_recorder` stays in its "recording" state from its own perspective but no more audio data arrives. The HUD timer keeps ticking; the user only finds out at the end when they click stop and get a zero-byte blob or truncated recording.

Purpose: fail-fast on mic stream death so the HUD can surface a clear error instead of silently producing bad recordings.
Output: updated `content/audio-capture.js` that calls `stop()` when the audio track's `ended` event fires while `_recording` is true.
</objective>

  <action>
After `navigator.mediaDevices.getUserMedia({ audio: ... })` resolves and `_stream` is assigned, attach a listener on the first audio track:

```js
const track = _stream.getAudioTracks()[0];
if (track) {
  track.addEventListener('ended', () => {
    if (_recording) {
      // Track died mid-recording (permission revoked, device unplugged,
      // tab suspended). Stop so HUD's onStop callback fires with whatever
      // data we have and surfaces an error.
      try { stop(); } catch (_) { /* already stopped */ }
    }
  });
}
```

Add this right after the line that assigns `_stream = await navigator.mediaDevices.getUserMedia(...)` (around line 50-70 of `audio-capture.js` — adjust to match the actual location).

Do NOT change the MIME-type negotiation, the bitrate (32000), the chunk interval, or the MIN_BLOB_BYTES guard. Only add the listener.
