#3

Streaming SOAP & live waveform — keep GPT-4o-mini, just flip stream=True

Same models, just streamed

Yes — both Whisper and GPT-4o-mini stay. Whisper is non-streaming by nature (returns full text after audio is processed), but GPT-4o-mini supports SSE streaming out of the box. The waveform comes from the browser's MediaRecorder + AnalyserNode — no backend touch.

Two independent perceived-latency wins

  • Waveform — kicks in during recording. Pure client-side. Solves "is the mic listening?" anxiety. No API change.
  • Streaming SOAP — kicks in after Whisper returns transcription, while GPT-4o-mini formats it. Tokens appear in ~200-400ms of first token, instead of waiting 1.5-3s for the full response.

Backend · Flask · extension_api.py
// Today (blocking):
response = client.chat.completions.create(
    model="gpt-4o-mini",
    messages=msgs,
    temperature=0.1,
)
soap = response.choices[0].message.content
return jsonify({"soap": soap})

// After (streaming):
def stream_soap():
    stream = client.chat.completions.create(
        model="gpt-4o-mini",
        messages=msgs,
        temperature=0.1,
        stream=True,
    )
    for chunk in stream:
        delta = chunk.choices[0].delta.content or ""
        if delta:
            yield f"data: {json.dumps({'t': delta})}\n\n"
    yield "data: [DONE]\n\n"

return Response(stream_soap(),
    mimetype="text/event-stream")
Client · content/api-client.js via SW proxy
// Service worker handler (already supports fetch proxy):
async function handleStreamSoap(payload, port) {
  const resp = await fetch(API + "/api/soap-stream", {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify(payload),
  });
  const reader = resp.body.getReader();
  const decoder = new TextDecoder();
  while (true) {
    const { done, value } = await reader.read();
    if (done) break;
    for (const line of decoder.decode(value).split("\n")) {
      if (line.startsWith("data: ")) {
        const { t } = JSON.parse(line.slice(6));
        port.postMessage({ type: "SOAP_TOKEN", t });
      }
    }
  }
}

function attachVisualizer(stream, canvas) {
  const ctx = new AudioContext();
  const src = ctx.createMediaStreamSource(stream);
  const analyser = ctx.createAnalyser();
  analyser.fftSize = 256;
  src.connect(analyser);
  const bins = new Uint8Array(analyser.frequencyBinCount);
  const g = canvas.getContext("2d");
  (function draw() {
    requestAnimationFrame(draw);
    analyser.getByteFrequencyData(bins);
    g.clearRect(0, 0, canvas.width, canvas.height);
    g.fillStyle = "#10b981";
    const bw = canvas.width / 24;
    for (let i = 0; i < 24; i++) {
      const v = bins[i * 4] / 255;
      g.fillRect(i * bw, canvas.height/2 - v*30, bw - 2, v * 60);
    }
  })();
}

Three layers of preset

Layer 1 · Built-in defaults

Conciso / Padrão / Detalhado — ship with the extension. Same prompt skeleton, three verbosity dials.

Layer 2 · Specialty packs

Pediatria / UPA / Triagem / Internação — preset-of-presets. Chosen at install. Changes default tone + which fields are emphasized (e.g. UPA prioritizes red flags).

Doctor names a voice ("Dr. Silva — pronto-socorro") and edits the underlying prompt + few-shot examples. Saved per account. Sync across devices.

How voice composes the GPT prompt at runtime

extension_api.py · prompt assembly
def build_soap_prompt(transcript, voice):
    base = SOAP_TEMPLATE_BASE
    verbosity_rule = VERBOSITY_RULES[voice["verbosity"]]
    perspective_rule = PERSPECTIVE_RULES[voice["perspective"]]
    emphasis_rules = "\n".join(EMPHASIS_RULES[e] for e in voice["emphases"])
    custom = voice.get("customRules", "")

    msgs = [{"role": "system", "content": f"{base}\n{verbosity_rule}\n{perspective_rule}\n{emphasis_rules}\n{custom}"}]
    for ex in voice.get("fewShots", [])[:3]:
        msgs.append({"role": "user", "content": ex["complaint"]})
        msgs.append({"role": "assistant", "content": ex["output"]})
    msgs.append({"role": "user", "content": transcript})
    return msgs

Why it works: few-shots are the highest-leverage personalization for LLM output. A doctor who pastes 2 of their own SOAP examples gets a model that mimics their style closely — way better than fiddling with prompt instructions.

#11

Voice commands — how the wake word + grammar work

Two-stage pipeline. Stage 1 runs locally and only listens for the wake word ("TF" or "Toca"). Stage 2 only fires after wake — captures the next ~2s, sends to Whisper, parses against a fixed grammar, dispatches the action.

The flow, end to end

1
Always-on local wake word
Web Audio API runs a tiny on-device model (Porcupine.js or a minimal MFCC + cosine match for "TF"). No network. ~3MB model. ~5% CPU.
↓
2
Wake fires → 2s capture window
Visual: HUD pulses + "Ouvindo..." chip appears. Audio is buffered locally; if no speech detected in 2s, abort silently.
↓
3
Whisper transcribes the 2s
Same Whisper endpoint as SOAP. Optimization: tiny clip → ~600ms round-trip on Cloudflare Tunnel.
↓
4
Grammar match (fuzzy)
Levenshtein-distance match against ~12 commands. Threshold 0.85. Best match wins. No match → toast "Comando não reconhecido".
↓
5
Dispatch existing action
Each command maps to an existing HUD function: finalizar(), openPrescription(), processDischarge(), etc. Reuses everything you already built.

The command grammar

content/voice-commands.js
const COMMANDS = [
  { match: /finaliz(ar|a)( paciente)?/i,    fn: "finalizePatient" },
  { match: /abr(ir|e) receita/i,            fn: "openPrescription" },
  { match: /(adicionar |novo )?atestado/i,  fn: "openAtestado" },
  { match: /baú médico/i,                   fn: "openBauMedico" },
  { match: /limpar (soap|prontuário)/i,     fn: "clearSoap" },
  { match: /salvar (consulta|prontuário)/i, fn: "saveForm" },
  { match: /imprim(ir|e)( receita)?/i,      fn: "printPrescription" },
  { match: /cancelar/i,                     fn: "cancelOp" },
  { match: /modelo (.+)/i,                  fn: "selectTemplate" },
  { match: /voz (.+)/i,                     fn: "selectVoice" },
];

function dispatch(transcript) {
  const t = transcript.toLowerCase().trim();
  for (const c of COMMANDS) {
    const m = t.match(c.match);
    if (m) return { fn: c.fn, args: m.slice(1) };
  }
  return null;
}

Example interactions

→ saves form, opens prescription, prints, discharge, returns to list
🎙 "TF... modelo GEA menos de um ano"
→ fuzzy matches "GEA <1a" template, opens prescription
🎙 "TF... voz pronto-socorro"

🎙 "TF... cancelar"
