# Clinical Safety & Intended Use

Toca Ficha Dr. is a documentation **automation tool** for physicians working in pediatric emergency / urgent-care settings on the G-Hosp electronic medical record system. This document defines what the tool is, what it isn't, and the safety boundaries every user must respect.

## TL;DR — the four rules

1. **The doctor is the author.** Every output the AI produces (transcription, SOAP note, CID-10 suggestion) is a draft for the physician to review and edit. The physician's CRM is what stamps the record, and the physician is professionally responsible for everything saved.
2. **Review before save.** No SOAP note, prescription, or discharge form is committed to the patient record without an explicit click by the physician. The side panel's "Alta e voltar" button triggers a confirmation prompt before submitting discharge and returning to the patient list. SOAP, prescription, and print are separate manual steps the doctor must complete before discharge.
3. **This is not a clinical decision support system.** It does not diagnose, triage, dose, or prescribe. It transcribes what the physician dictates, formats it as SOAP, suggests a CID-10 code based on the SOAP text, and automates form filling.
4. **Not for emergencies that need immediate action.** Critical care, code-blue scenarios, anaphylaxis, sepsis recognition, etc. should not wait for a transcription pass. Document after stabilization, or fall back to direct G-Hosp interaction.

## Regulatory framing

### CFM Resolution 2.454/2026

The Conselho Federal de Medicina's resolution on AI in medicine permits AI as a tool of physician support provided:

- Outputs are reviewed by the physician before becoming part of the medical record ✅ enforced by the side panel's review-then-finalize gate
- The physician retains authorship ✅ the CRM bound to the G-Hosp account stamps each record
- The patient is informed when AI is used ⚠️ disclosure is the prescribing clinician's responsibility — not enforced by the extension

### LGPD (Lei 13.709/2018)

- Health data is "sensitive personal data" under Article 11
- The extension does **not** store audio recordings, transcriptions, SOAP notes, CID codes, or any clinical data on its servers
- Audio is processed in memory by OpenAI (via the Flask backend in `backend/`) and discarded after transcription
- Identity data (email, name, password hash, session tokens) is processed by Clerk Inc. (USA/EU) — see `landing/privacidade.html` for the full sub-processor disclosure and Brazil-EU adequacy decision (2026-01-26) citation

### ANVISA

The extension is positioned as an **automation/documentation tool**, not a Software as a Medical Device (SaMD) under RDC 657/2022. The clinical decision (diagnosis, treatment, prescription) is always made by the licensed physician. Any feature that would shift this classification (e.g., automated dosing calculations applied without review, automated diagnosis without physician input, image-based detection of pathology) is **out of scope** for this codebase.

## Intended use

| Use case | Status |
|----------|--------|
| Transcribe a doctor's verbal account of a patient encounter into SOAP format | ✅ |
| Suggest a CID-10 code that the doctor reviews before filling | ✅ |
| Auto-fill prescription templates the doctor has pre-configured | ✅ |
| Auto-fill the discharge form (with doctor verification of referral choice) | ✅ |
| "Alta e voltar" — discharge and return to list after doctor confirmation | ✅ |
| Print prescriptions and the atestado after the doctor clicks finalize | ✅ |
| Replace the doctor's clinical reasoning | ❌ never |
| Triage / prioritize patients in the waiting room | ❌ out of scope |
| Diagnose without physician review | ❌ never |
| Calculate a drug dose and apply it automatically without review | ❌ never |
| Automate any aspect of code-blue / cardiac-arrest care | ❌ explicitly not designed for this |
| Use on adult patients in non-pediatric workflows | ⚠️ may work but selectors and CID database are pediatric-tuned; not validated |
| Use on EMRs other than G-Hosp at UPA Bento Gonçalves | ⚠️ DOM selectors are tightly coupled; not portable without selector-config rewriting |

## Failure modes the user must understand

### Whisper transcription errors

OpenAI Whisper has a measurable error rate on Brazilian Portuguese medical terminology. **Drug names, dosages, anatomical structures, and rare diagnoses are the highest-risk transcription targets**. The doctor MUST proofread the SOAP draft before clicking "Finalizar Paciente" or "Salvar e Imprimir". Auto-clipboard-copy of the SOAP makes manual paste-and-edit easy.

### CID-10 suggestion errors

The CID-10 suggestion is generated by GPT-4o-mini from the SOAP text. It is correct often enough to be useful but wrong often enough to require review. The side panel presents it as a *suggestion*, not a fait accompli. The doctor must verify the code matches the actual clinical impression before saving.

### DOM automation breakage

G-Hosp can change its UI without notice. The extension's selectors (especially around CID input, the prescription dialog, and discharge forms) can break silently. **The most dangerous failure mode is "looks like it worked but didn't"** — a Gravar click that didn't actually save, a CID fill that the autocomplete didn't accept. Defenses in place:

- Explicit verification steps after each automation (e.g., `verifyDischargeComplete` polls for the Gravar button to disappear)
- "Trust the submit" with fall-through to manual paths when verification is ambiguous
- Console logging at every step under `[Toca Ficha Dr.]` prefix — open DevTools if a flow seems wrong
- Rolled-up `transcribe_success` audit telemetry captures `audioBitsPerSecond`, `mimeType`, and blob size for diagnosing rare quality issues

If a flow ever produces a "saved" indicator that turns out to be wrong, **document it in the doctor's session log and report via SECURITY.md if it's a recurring failure pattern**.

### Microphone availability

The extension uses MediaRecorder via the browser. If the microphone is muted at the OS level, in `chrome://settings`, or by Bluetooth disconnection, recording can produce silent or zero-byte audio. The extension surfaces a "audio source muted" message via `track.ended` / `track.mute` listeners. If recording produces nothing useful, **the doctor falls back to typing directly into G-Hosp** — the SOAP fields are never required to come from the extension.

### Network failures

The Flask backend on Mac Mini may be unreachable (Cloudflare Tunnel down, Mac Mini offline, OpenAI API outage). The backend source now lives in `backend/` inside this repo. Recording may complete but transcription fails. The audio is held in browser memory and *not* persisted. The doctor should retry, or fall back to manual documentation.

## Disclosure to patients

Brazilian legal practice (LGPD + CFM) requires the patient be informed when AI processes their health data. The extension does **not** display a notice to the patient — it is operated by the physician inside the EMR. **The disclosing party is the physician, not the software.**

Recommended language for the physician's verbal disclosure (Portuguese):
> "Vou usar uma ferramenta que transcreve nossa conversa para preencher seu prontuário mais rápido. A gravação não é guardada e eu reviso tudo que foi escrito antes de salvar. Tudo bem?"

If the patient declines, the physician should disable recording and document manually for that encounter.

## Reporting clinical safety incidents

A "clinical safety incident" is any case where the extension contributed to a near-miss or actual harm to a patient (e.g., a CID code that was saved without review and led to billing/follow-up confusion; a prescription template that was printed with the wrong drug; SOAP content that misrepresented the encounter).

**Email:** contato@tocafichadr.com.br
**Subject:** `Safety incident — <date>`

Include:
- Date, anonymized patient identifier (e.g., "patient #4 of 2026-05-02 evening shift")
- What happened
- Whether the extension's behavior was the proximate cause, a contributor, or unrelated
- What you'd want to change about the extension to prevent recurrence

These reports drive the priority list in `docs/NEXT-STEPS.md` and may trigger out-of-band hotfixes.

## Things that ARE explicitly designed for safety

| Mechanism | Where | Defends against |
|-----------|-------|-----------------|
| Review-then-finalize gate on every save | `content/dom-engine.js` `runSimplesPrescription` + side panel "Alta e voltar" | Auto-saves of unreviewed AI output |
| 30s safety timeout on dialog locks | `_lockDialog` in `dom-engine.js` | Doctor stuck in a frozen modal during a hung save |
| Mutex on Finalizar + prescription template clicks | `state.rxFinalizing` / `rxRunning` in side panel | Double-click producing duplicate prescriptions or saves |
| CSP without inline scripts | `manifest.json` `extension_pages` | XSS vectors via injected content |
| 30s `AbortSignal.timeout` on transcribe fetch | `service-worker.src.js` `_handleTranscribe` | Mid-shift hangs if OpenAI Whisper stalls |
| `track.ended` listener | `audio-capture.js` | Mic disconnect mid-recording producing silent audio |
| HTML sanitizer on SOAP before rich-text write | `content/dom-engine.js` (commit `a77f194`) | Backend-compromise SOAP injection |
| Bearer-auth gate on backend `/api/*` | `backend/emr_automation/auth.py` | Open-relay against the OpenAI account |
| Lazy User provisioning + Clerk JWKS verify | `auth.py` `_resolve_user_id` + `_verify_clerk_jwt` | Forged tokens, server-side cross-tenant access |

## Versioning and audit trail

- The extension version is in `manifest.json` `version`. Each released version corresponds to a git tag (`v3.0.0`, `v3.0.1`, ...).
- The Flask backend tags are git SHAs in this repo (`backend/`).
- Every patient-encounter audit event (`transcribe_success`, `finalize_patient`, `discharge_complete`) is logged to the Flask backend's audit table, **without clinical content** — only action type, timing, and authenticated user ID.
- A doctor can request their own audit-trail export at any time. Email contato@tocafichadr.com.br.
